# 开源质量审计与分阶段优化规划

## Goal

只读审计现有架构、目录、代码与注释、性能、视觉和开源体验，形成基于证据的优化优先级、验收指标与分阶段方案；未经批准不改源代码。

## Requirements

- R1：基于当前仓库给出系统设计、目录组织、编码与注释、性能响应、视觉体验的可执行优化建议，区分确认事实、推断和待验证项。
- R2：同时评估安装信任、宿主兼容性、测试发布和贡献者体验，避免以功能数量替代产品质量。
- R3：建议按收益、风险、依赖与验收方式排序；Star 数仅作为愿景，不作为工程验收指标。
- R4：本任务只产出审计与规划文档；未经下一轮明确批准，不修改源代码、不运行安装器、不触碰真实宿主与用户运行目录、不提交或推送。
- R5：保留任务开始前已有的 5 个修改文件，不覆盖、不回滚。

## Acceptance Criteria

- [x] 覆盖 R1 的五个维度与 R2 的开源基础，重要结论有可核对的源码位置或命令结果。
- [x] 核验 Node/Python 测试入口和插件生成副本一致性，记录实际结果及环境限制。
- [x] 给出推荐路线与备选路线，记录阶段验收、迁移风险和回滚约束。
- [x] 性能数值明确为实测或建议目标，未做宿主实测时不宣称已经验证视觉与响应。
- [x] 规划任务保持 planning，产品代码无本轮变更；实施前另行确认首批范围。

## 已确认事实

- 产品是输入区附近的一行状态条，不是仪表盘；术语以根目录 CONTEXT.md 为准。
- 当前存在 core/ 与 statusbar/ 源码、根级 Python 数据模块，以及 plugins/zcode-statusbar/ 扁平分发副本。
- 已有单元测试、跨模块契约、注入路线 ADR、生成副本漂移检查机制，不是从零建立工程化。
- 当前根 README 只有标题与一句介绍；package.json 的 test 仅执行 Node 测试。

## 不在本轮范围

- 不扩展产品功能、不重写框架、不承诺 GitHub Star 数，不将尚未确认的视觉偏好固化为需求。
- 不创建实施子任务、不进入执行阶段；实施范围与宿主支持策略由用户审阅路线后确定。
