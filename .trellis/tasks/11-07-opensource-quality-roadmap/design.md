# 开源质量优化路线（待审阅，不授权实施）

## 目标与判断

把“用户敢装、数字可信、宿主升级可维护、外部贡献能合并”作为质量目标。万星是愿景，不是可以由代码重构保证的结果；还受宿主用户规模、独特价值、传播与持续维护影响。

依据见 `research/audit.md`。当前优点是无框架低依赖 UI、纯函数统计、安装回滚与副本同步已有测试。主要缺口是跨模块正确性、生命周期、工程门禁和公开使用说明，而不是缺一套更重的前端框架。

## 路线比较

| 路线 | 收益 | 代价与风险 | 建议 |
| --- | --- | --- | --- |
| A：正确性与生命周期 → 门禁与文档 → 局部架构深化 → 视觉打磨 | 直接修复用户可见错误，回归面可控 | 需先补集成夹具，不会立刻得到“焕然一新”的目录 | 推荐 |
| B：先目录重组与风格统一 | 导航短期更整齐 | 移动 Python 导入、扁平打包与资源路径，错误链仍存在 | 不先做 |
| C：全面 TypeScript/React 重写 | 长期可统一工具链 | 高迁移成本、宿主注入与构建链更复杂，现阶段收益证据不足 | 暂不做 |

本轮不改动已接受的 ADR-0001：完整注入、引擎补丁与 ZIP 预注入路线。可以把这些能力内部隔离，但不能未经批准删减为最小注入；若将来改变产品侵入策略，需要新 ADR 与兼容迁移。

## 优先级与验收

### 第一批：P1 正确性、生命周期、最小质量门禁

1. **F1 幂等与清理**：入口安装实例守卫，统一 dispose 管理采样、观察器、监听器、定时器、DOM、宿主样式恢复。旧实例先清理，新实例再挂载。
   - 验收：同页注入 10 次仅一条状态条、一套采样资源；dispose 后自有资源计数归零；宿主 DOM 重建可恢复，不靠无限 body 观察重绘。
2. **F2 活动状态与采样分离**：以最后字符变化/明确生成状态判断活跃，而非最后读到节点的时间。优先使用现有状态桥与宿主 store；无法确认时保留估算标签和保守降级，不把字符估算包装成精确 token。
   - 验收：静态消息不持续发布生成中；完成后回到核实会话均；隐藏窗口与闲置停止高频读取；中英文本、代码块、新轮切换和文本长度相等的消息替换有夹具。
3. **F3 会话归属**：来源与归属分别建模，依实际 parent_id 关系路由子代理。
   - 验收：A/B 双窗口各有独立子代理，只归属本窗口；未知身份不混入；窗口切换与旧响应乱序不显示另一会话数据。
4. **F4 摘要与明细分离**：会话全量累计、有限趋势和有限明细使用独立范围；在只读 SQLite 侧聚合摘要，不把所有历史搬到 renderer。
   - 验收：8000+ 行仍与 SQL 基准一致；明细限制不改变累计；多窗口不抢占统计正确性；保留输出体量护栏。
5. **最小门禁**：一个统一验证入口，执行 Node、Python、同步漂移与 manifest/契约一致性检查；加入仓库 CI。先用现有运行时测试，再逐步扩充支持版本矩阵，不凭本机版本宣称广泛兼容。

### 第二批：P1/P2 安装信任与公开可用

- 根 README：真实浅/深色截图、短演示、价值说明、支持平台/宿主版本、运行依赖、最短安装路径、明确修改哪些宿主文件、重启说明、卸载恢复、失败排查、数据与联网边界。
- 核对 marketplace 与两份 manifest 的仓库地址、版本和发布身份。保留独立插件包可安装性，不能让 README 指向仅工作区存在的路径。
- 提供只读 doctor/check 诊断思路：解释器、宿主版本、锚点、schema、运行时文件、注入状态、最近错误；用户主动触发，日志脱敏，不上传凭据、对话正文与完整路径。
- 明确兼容失败策略：不匹配时不盲补丁，保留宿主可用性，提供可执行恢复指引。现有回滚、豁免标记和安装锁不因“精简代码”而删除。
- 在已有 HTTPS、来源/路径/文件白名单、SHA256 基础上，增加构建到安装的产物往返测试。可信发布签名是进一步供应链建设，不能把同源哈希误称为独立身份认证。
- 补充 CONTRIBUTING、SECURITY、Issue/PR 模板、CHANGELOG；说明源码正本与生成物，标出适合外部贡献的低风险入口。

### 第三批：P2 深化模块，而非机械拆文件

保持现有目录先清接口，再在必要时移动文件：

```text
core/                     安装、宿主接入、运行时编排的源码正本
  runtime/                数据泵与进程生命周期、窗口路由、动作分发
  install/                宿主发现、事务安装/恢复、宿主兼容探测
  update/                 来源校验、下载校验、原子部署、回滚
statusbar/                采样、展示状态、DOM 视图、主题与色阶
data/                     SQLite 查询与快照投影；从根级模块渐进迁移
tests/                    unit / integration / fixtures；先补测试再重分目录
plugins/zcode-statusbar/  独立分发副本，由现有同步/构建脚本生成
docs/                     面向使用者与贡献者的稳定文档，不依赖临时任务路径
```

这是目标职责图，不是要求一次创建所有目录。对外只暴露小接口，例如宿主探测、运行时 start/stop、窗口快照、UI mount/update/dispose；文件内的小函数无需全部公共导出。测试依接口行为，不绑死私有拆分。

- loader 保留组合根，安装/更新/数据泵/窗口路由各自隐藏复杂度，禁止新增全局万能 utils。
- 明确资产映射与版本/文件清单的单一源；生成同步副本、独立校验白名单和 manifest，独立校验器不必 import 整个运行时。
- UI 中样式、派生展示状态、DOM/弹层、宿主圆环适配分离；保持无框架运行路径，可以通过小构建脚本组装，不为拆分强加大型 bundler。
- 为跨语言数据契约加 schemaVersion、归属身份、生成时刻与数据状态；确需并发时带 request/sequence 标识抵御旧响应。
- 规范化层做有限数值、状态、范围验证，不让各展示函数重复猜测 payload 形状。优先 JSDoc/checkJs 与格式规则试点，不以全仓改语言作为前提。
- Python 与 JS 口径使用共享 golden fixtures 验证，逐步确定各指标唯一计算归属；不在一次重构中同时改统计定义。
- 将历史移植说明、PRD 编号、并行代理对齐记录移入稳定文档；代码只保留不可自表达的 WHY、不变量、安全与回滚约束。契约字段注释、复杂 SQL 口径说明不能盲删。

迁移策略：接口外置 → 回归测试 → 原路径兼容包装 → 更新资产映射 → 包装副本/ZIP 往返校验 → 最后移除兼容包装。每个阶段可回滚，不同时改变安装布局与统计口径。

### 第四批：P2 视觉与交互

保持“输入区的一行原生状态条”：不扩展成仪表盘，不新增第二上下文圆环，不用闪烁与高饱和色争夺注意力。

- 信息层级：默认核心读数，次要数据进入详情；是否默认折叠闲置子代理或隐藏轮次/步数属于产品选择，未确认前保留现状。
- 稳定宽度：tabular-nums、量级格式、速度与单位紧凑组合；窄窗口允许渐进隐藏次要标签，弹层跟随视口边界，避免溢出。
- 状态明确：加载、未知、无会话、估算、核实、过期、错误分别展示；未知不等于 0，估算可用 `≈` 或明确文案，不能只靠呼吸动画与颜色。
- 主题跟随宿主实际主题变化，不只依赖系统 prefers-color-scheme；色阶做浅/深主题对比度与色觉检查。
- 键盘可操作、focus-visible、aria-expanded/controls 与弹层焦点返回；支持 reduced-motion；不要让读屏按 10Hz 播报数字。
- 圆环修改只触及目标 style 属性，保存并恢复宿主原值。
- 用离线假宿主页面覆盖浅色/深色、窄栏、125%/150% 缩放、超大数值、缺失数据、生成/完成/子代理运行状态。固定时钟和动画后做截图回归，再在登记版本的真实宿主复核。

## 性能目标与测量

以下是拟议验收预算，不是实测，也不是已批准的性能承诺；先记录同一硬件/系统/宿主/数据库规模的插件关闭基线，再做增量对比。

| 场景 | 拟议目标 | 验证 |
| --- | --- | --- |
| 闲置且静态 DOM | 无 100ms 全局扫描与估算事件风暴 | 假时钟统计读取/发布次数，宿主 profile 复核 |
| 流式生成 | 采样最多 5–10Hz，UI 按值变化合并更新 | 不同流速与长文本回放 |
| 本地菜单/弹层交互 | p95 <100ms | fixture 页面重复交互，宿主复核 |
| 已完成统计更新 | 默认配置下 p95 ≤2s，须与既有 ≥1500ms 节流共同验证 | DB 写入→查询→分发→render 全链路计时 |
| 挂载恢复 | 身份与锚点就绪后 1s 内恢复 | 不把宿主未就绪计为插件挂载耗时 |
| 多次注入与卸载 | 资源计数稳定，dispose 归零；长时运行无持续增长趋势 | 10 次重载、100 次会话切换及长时 profile |
| 大会话查询 | 记录 1万/10万行合成库的 p50/p95 与 payload 大小，再定查询预算 | 只读 fixture、EXPLAIN QUERY PLAN；不向宿主数据库擅自建索引 |

CPU/RSS 门槛待基线测量后确定，不能把 VM 中查询次数冒充宿主 CPU 基准。按 sid/变更戳缓存、摘要投影、减少 executeJavaScript 和 DOM 写入优先于微优化语法。

## 开源增长与范围外建议

先验证 ZCode 目标用户是否愿意安装以及最关心哪项读数，再用安装完成率、首次出数成功率、升级成功率、故障恢复率、留存与外部首次贡献耗时衡量质量。默认不加遥测；可通过自愿反馈与脱敏复现收集证据。

README 的短演示展示一个明确痛点，公开支持矩阵与变更记录，保持可复现 Release，并为外部贡献者准备“无需安装真实宿主即可跑 UI”的入口。增加宿主支持数量或开发通用 SDK，等真实第二种适配需求出现再评估，不预造插件平台。

## 待用户决定

建议第一批只做 F1–F4 正确性/生命周期修复、对应集成测试与最小 CI；不同时改产品信息布局、reset 语义或侵入路线。第一批范围尚未批准，任务保持 planning。

reset 的产品语义、支持平台与宿主版本范围、UI 默认信息取舍将在对应阶段单独确认，不阻挡本轮审计交付，也不视为已默认采用上述建议。
