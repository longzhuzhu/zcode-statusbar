# ADR-0001: 接入方式完整复刻 zcode-token-usage-statusbar 的注入路线

- 状态：已接受（2026-11-06）
- 决策人：用户（访谈确认）

## 背景

ZCode 没有正式的 statusbar 插件接口（无 `registerStatusBarItem` 类 API；官方插件 UI 仅 MCP Apps 内联页/侧栏，位置与实时性均不满足状态条需求）。要做出输入区附近的状态条，必须选择非官方接入手段。

## 决策

新插件完整复刻 zcode-token-usage-statusbar 的接入链路：

- 修改 app.asar 主入口，追加 file:// 动态 import 加载稳定运行目录中的 loader；
- Electron 主进程注入 + renderer 状态桥（含 React fiber 兜底）；
- 引擎补丁（glm/zcode.cjs）与 macOS 更新 ZIP 预注入同样保留；
- 稳定运行目录、热更新、升级保护机制照搬。

## 理由

- 与原插件同等侵入带来最强的功能兼容性与行为一致性（含自动压缩阈值等行为功能）；
- 安装/卸载机制已有成熟实现与回归测试可直接参考；
- 用户明确选择该路线而非最小注入。

## 后果与义务

- 原插件已知的 3 个卸载闭环缺口（引擎 restore 未挂接、更新 ZIP 无撤销链、独立安装器悬空注入行）必须在新项目中补齐；
- 宿主升级耦合风险全量继承：DOM、store、bundle 锚点、SQLite schema 变动都可能破坏插件；
- 不能宣称"纯只读、零侵入"；修改宿主文件的告知义务保留。

## 备选方案

- 最小注入（仅状态条 UI + 只读数据，排除引擎补丁/ZIP 预注入）：维护面小，但功能与原插件不完全对齐 — 被否。
- MCP Apps 页面：零侵入但位置/实时性不满足 — 不可行。
